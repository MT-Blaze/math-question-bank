### 关于「能不能提取源代码」
- `resources/app.asar` 解开后**只有 3 个文件**：`electron/main.js`、`electron/preload.js`、`package.json`，不含业务代码。
- 真正的业务在 `resources/app-next`：`.next` 是**编译后的服务端产物**，`server.js` 是**混淆代码**；`src/` 里只剩 1 个无关的 `tikz-snapshot.ts`。
- 作者的 GitHub 仓库当前返回 **404**（私有或已删除），无法在线取源码。
- 结论：**拿不到可读源码**；能稳定拿到的是**数据库结构（34 张表）**，已导出为
  `outputs/参考题库App-数据库结构.sql`。

## 二、参考应用的数据模型亮点

### 1. 题目（questions）字段更“考试化”
`type / difficulty(1-5) / title / number / year / stem / options(JSON) / answer / analysis / analysis_methods(JSON) / translation / confidence / source / region / video_url / remark / conditions(JSON) / option_columns`
→ 有「年份、地区、视频、翻译、条件、选项列数、AI 置信度」，比我们多了**考试元数据**与**录入质量指标**。

### 2. 标签与知识点是规范的多对多
- `tags(id,name)` + `question_tags(question_id,tag_id)`
- `knowledge_points(id,name)` + `question_knowledge(question_id,kp_id)`
→ 而不是像我们存在字符串 / 大纲 JSON 里，便于聚合统计与重命名。

### 3. 目录树 + 多空间
- `spaces(id,name,tier,readonly,sort)`：多空间（个人空间等）
- `catalogs(id,space_id,parent_id,module,name,sort)`：可递归目录树，且按模块区分（题库/课件/文件）
→ 我们的「册次→章节→小节→考向」是固定四级，没有用户自定义目录树与多空间。

### 4. 结构化组卷
- `papers` → `paper_sections`（分区、说明、可见性、排序）
- `paper_items`（题目、分值、留白 cm、图排版、是否锁题、来源、渲染覆盖、**快照 JSON**、内容 hash）
- `paper_assets` / `paper_item_assets`（试卷资产，含上传图与组卷临时 TikZ 图，`origin` 区分可回收性）
- `paper_generation_runs`（随机种子、规则 JSON、诊断、耗时）
→ 我们的 `papers + paper_questions` 只有题目顺序与分值，没有分区、快照、规则与生成记录。

### 5. 可回滚的批量导入
- `import_batches`（源文件 sha256、plan/preview hash、backup/report 路径、状态、reimport_of）
- `import_batch_questions/images/catalogs`（导入映射、disposition、imported_hash）
- `import_file_cleanup_queue`
→ 导入是「先出计划 → 用户确认 → 提交 → 可回滚」，还有备份与报告。我们是任务式导入，直接入库，无批次审计。

### 6. 课件与知识卡片
- `courseware` + `courseware_sections` + `courseware_blocks`（question/text/heading/image，题目块存快照）
- `knowledge_cards` + `knowledge_card_segments`（定义/证明/注记等分段）+ `knowledge_card_links`（前置知识依赖图）
→ 我们没有课件模块；`lesson_plans` 更偏「教案」而非「课件/知识卡」。

### 7. TikZ 版本管理
- `tikz_diagrams` + `tikz_versions`（父版本、渲染图、参考图、源码 hash、渲染器版本、生成模式、模型、指令、上下文 hash、宽高）
→ 我们只有题目上的 `tikz_code` 与 TikZ 资产，缺少**版本树与 AI 生成溯源**。

### 8. 其它
- `images`（图片库）、`shares` + `share_log`（分享）、`settings`（KV）、`schema_migrations`（迁移记录）。

## 四、异同对照

| 维度 | 参考应用 | 本项目 | 评价 |
|---|---|---|---|
| 交付/技术 | Electron + Next.js + React，编译混淆 | FastAPI + 原生 JS，无构建 | 我们**更易改、更轻、可完全离线**；对方**界面更现代、可打包** |
| 数据表 | 34 张 | 7 张 | 对方模型更细；我们更紧凑 |
| 标签 | `tags` 多对多 | `tags` 逗号字符串 | 对方更规范，值得借鉴 |
| 知识点 | `knowledge_points` 多对多 | 考向树 + `question_topics` | 各有侧重：我们「考向」更贴合备考，对方「知识点」更通用 |
| 自定义目录 | `catalogs` 树 + `spaces` 多空间 | 固定四级教材分类 | 对方更灵活 |
| 组卷 | 分区/分值/留白/快照/规则/种子/生成记录 | 题目顺序 + 分值 | 对方**结构化组卷**明显更强 |
| 导入 | 批次 + 计划 + 备份 + 回滚 | 任务式直接入库 | 对方**可审计可回滚**，值得借鉴 |
| 课件 | courseware + blocks | 无（有教案） | 对方有课件，我们有教案，定位不同 |
| 知识卡片 | cards + segments + 前置依赖 | 无 | 可作未来扩展 |
| TikZ | diagrams + versions | 题目级 tikz_code/assets | 对方版本管理更完整 |
| 查重 | 未见查重表 | 指纹 + SimHash + 文字片段 + 图形 hash | **我们更强** |
| 考向树/大纲 | 无对应 | TXT ↔ Web 双向同步 | **我们独有** |
| OCR/AI | `/api/ocr/*`、`/api/ai/*`（含每日限额、识别测试） | 多供应商 AI、MinerU、视觉 OCR、TikZ AI | 各有实现，我们**接入方式更多** |
| 分享/多用户 | shares/share_log、多空间 | 本地令牌单用户 | 对方偏协作，我们偏单机 |
| 题目元数据 | 年份/地区/视频/翻译/条件/置信度 | 适用年级/试卷分类/来源/难度 L1-L5 | 可互补 |
| 导出 | HTML/LaTeX/PDF/JSON/archive/答题卡 | tex/PDF/Word/zip | 对方多 HTML/JSON/答题卡 |

## 五、能借鉴什么、不建议做什么

### 建议引入（按性价比排序）
1. **标签规范化为 `tags` + `question_tags` 多对多**（保留现有字符串字段做兼容迁移）。
2. **题目扩展字段**：`year`、`region`、`video_url`、`translation`、`conditions`、`option_columns`、`analysis_methods`。
3. **结构化组卷**：给 `paper_questions` 增加 `section/score/solution_space/figure_layout/locked/snapshot_json/content_hash`，并增加「组卷规则 + 随机种子 + 生成记录」。
4. **导入批次与回滚**：为现有导入流程增加 `import_batches` 及 plan/report/backup，先出计划再确认。
5. **TikZ 版本表**：`tikz_versions`（父版本、模型、指令、hash），保留 AI 生成溯源。
6. **用户自定义目录树**（单空间起步）：`catalogs(parent_id, module, sort)`。
7. **知识卡片**（可选，长期）：`knowledge_cards` + `segments` + `links`（前置依赖）。
8. **JSON/HTML/答题卡导出**（可选）。

### 不建议做
- **不要照搬 Electron + Next.js 架构**：与 `AGENTS.md` 的「无前端构建、FastAPI + 原生 JS、极简本地部署」硬约束冲突，等于推倒重写；且对方源码已混淆、仓库 404，无源码可搬。
- **不要直接复制其表结构全量迁移**：34 张表里有大量课件/分享/多空间能力，当前并不需要，先做最有价值的 3~4 项即可。

### 可以立即做的下一步
1. 出一份**增量迁移方案**：在现有 7 表基础上加 `tags`/`question_tags`、`question` 扩展字段、`paper_sections`/`paper_items`（或扩展 `paper_questions`）、`import_batches`。含 SQLite 迁移脚本 + 数据回填 + 测试。
2. 或先做**题目扩展字段 + 标签多对多**这一小步，风险最低、收益直接（筛选/统计立刻变强）。
