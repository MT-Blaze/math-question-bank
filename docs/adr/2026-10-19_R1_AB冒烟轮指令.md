【P0 · 先改三处，否则数据仍然不可信】

**P0-1 超时预算对齐老路（否则大卷必然降级，不是运气问题）**

改前（`routes_paper.py:915`）：
```python
PDF_METADATA_DEADLINE_SECONDS = 120
```
改后目标：`PDF_METADATA_DEADLINE_SECONDS = 240`，并且 `_call_pdf_metadata_ai` 里的 `timeout=` 也一并改为 240（否则 `min(180, 240) = 180`，仍然卡在 180）。
边界：**只改这一处快路径常量**；不许动 `AI_SPLIT_READ_TIMEOUT_SECONDS` / `AI_SPLIT_DEADLINE_SECONDS`。PR 描述里注明"这是 A/B 期的临时对齐，定稿时按实测 `ai_ms` 分布单独收紧"。

**P0-2 拆开 connect / read 超时（否则 connect 会被放大到 240s 且可重试一次）**

改前（`ai_http.py:128-135`）：
```python
    kwargs = dict(request_kwargs)
    kwargs["stream"] = True
    requested = float(kwargs.get("timeout") or 60)
    kwargs["timeout"] = min(requested, float(read_timeout) if read_timeout else 30.0)
```
改后目标：`kwargs["timeout"]` 归一化为二元组 `(connect, read)`：
- `connect = min(调用方给的 connect 或 60, 30.0)` —— connect 上限恒为 30s，不被 `read_timeout` 放大
- `read = min(调用方给的 read 或 60, read_timeout if read_timeout else 30.0)`

边界：
- 这是纯传输层改动，不许在 `_post_bounded` 内加任何业务判断（不认 provider、不认 task 类型）。
- `post_chat_completion` 签名不变；`stream=True` 那条分支不受影响。
- 现有 scalar 调用者的 connect 会从"等于 timeout"收紧到 30s，这是**行为变化**，PR 里必须写明。
- 全量 `pytest tests/` 仍须 1654 passed。

**P0-3 让"降级"变成会红的失败（本任务的核心要求）**

改前（`routes_paper.py:1033-1036`）：
```python
    except (TaskCancelled,):
        raise
    except Exception as exc:  # 超时/网络/坏JSON/条数不符 → L2 保正文降级
        return _degrade_clean_only(plan, exc, diagnostics)
```
改后目标：
1. 成功路径写 `diagnostics["ai_ok"] = True`，降级路径写 `False`。
2. `degrade_reason` 改为 `f"{type(exc).__name__}: {exc}"[:200]`（**异常类名必须进字符串**）。
3. 新增开关 `PDF_FASTPATH_STRICT`（默认 `0`）：置 `1` 时，`_run_fast_path` 的 AI 异常**直接向上抛**，不降级。

边界：
- `PDF_FASTPATH_STRICT` 只作用于 `_run_fast_path` 的 AI 异常分支；**不得**影响 L1（`plan.trustworthy=False` 是切块器的合法判定，不是失败）。
- `TaskCancelled` 无论 strict 与否都原样 `raise`。
- 生产默认 `0`，全量测试行为不变。
