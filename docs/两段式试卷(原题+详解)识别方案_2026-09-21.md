## 9. 已落地：两段式卷自动切分（2026-09-21）

### 9.1 用户场景与目标

用户手上这类卷子**有很多**，统一形态是：**前半 = 原卷（纯题干，无答案）**，
**后半 = 同一份卷子的「题干 + 答案 + 详解」版**。目标：**自动只解析后半段**，
从源头消掉「每道题被识别两遍、同一题的插图出现两套、末题吞掉整批图」。

### 9.2 检测判据（`mathbank/pdf_split.py::detect_solution_split`）

只看 PDF **文本层 + 页码**，不调 AI、不碰网络，上传瞬间即可完成。
**六道闸门全部通过才给结论**，任何一条不过就安静地退回整本解析（猜错会丢题）：

| # | 闸门 | 实测（三份真实卷） |
|---|---|---|
| 1 | 前半 ≥2 页、后半 ≥3 页 | 3~4 / 12~18 ✓ |
| 2 | 解析段「持续」：其内 ≥50% 的页带逐题标记（【答案】/【详解】/【解析】…） | 89~92% ✓ |
| 3 | 前半**一整页都不能**有逐题标记（保证切在真正的分界上） | 天然成立 |
| 4 | 前半的题号**全部**能在后半找到（直接防丢题） | 无缺失 ✓ |
| 5 | 两边题号都 ≥3 个 | 17~22 ✓ |
| 6 | **后半净字数 ≥ 前半的 2 倍**（后半是「题干+解析」而非纯答案） | 3.52 / 4.00 / 3.86 ✓ |
| **7** | **后半确实重印了题干**：后半「题号 → 首个逐题标记」之间的净字数中位数 ≥ 12 | 52 / 57 / 50 字 ✓ |

**第 7 条是后补的，专治「前半原题 + 后半只给答案解析、不重印题干」**：
把三份真实卷的后半按「题号→首个答案标记」的份额扣掉来模拟这种形态，长度比仍有
**2.43 / 3.16 / 2.75**（照旧 ≥2）→ 前六条**全都拦不住**，跳页会把题干整个丢掉。
唯一能区分的是「题号后面到底跟不跟题干文字」：真实样本中位数 57/59/58 字，不重印题干的形态是 **0**。
诊断里会输出 `back_stem_median` 供事后核对。

**为什么第 6 条是长度比而不是「题干回响率」**：真实样本里大庆 2023-2024 那份的文本层
**公式顺序被打乱**（`已知集合Axxx20Bxax10`），连续字符串匹配的回响率只有 **9%**
（另两份是 100%），拿它做闸会把这份明明安全的卷子挡在门外。长度比与文字顺序无关，
三份高度一致。回响率仍会算出来写进诊断供人核对。

### 9.3 分界点与页码处理（关键）

**分界点 = 第一个出现逐题标记的页**（0-based）。三份实测：第 5 / 5 / 4 页。
切出来的正是「含答案解析版」的第一页（页脚写着"第1页/共18页"）。

两条路线都**保持原始页号**，用户对着手上的 PDF 核对时不会错位：

| 路线 | 做法 | 页号处理 |
|---|---|---|
| **native_preferred / force_ocr** | 未填「页码范围」时，把 `target_page_indices` 收敛到解析段 | 页标记、`pdf_crop_*`、`pdf_page_*`、`_source_page` **全是原始页号** |
| **mineru_cloud** | MinerU 不认识页码范围 → **先把前半段物理裁掉**再送云端 | 整页原图仍用**原始 PDF + 原始页号**渲染；MinerU 返回的逐页文本按 `start_page` **补齐空页**，下标还原成原始页号 |

顺带修掉了 §2 的 P0：`find_source_page_by_overlap` 现在从页文本的
`MATHBANK_PDF_PAGE:` 标记取**绝对页号**（取不到才退回局部下标），
所以「用页码范围」不再错挂配图。

## 10. 已落地：配图「图形替换」（手工通道）

### 10.1 为什么不做自动擦水印

水印恒为**纯中性灰 `rgb(207,207,207)`**（R−B=0），技术上可做「把某个灰度带的平坦灰块抹白」，
但数学题里「阴影部分面积」常用浅灰填充 —— 一刀切会把合法填充一起抹掉，**误伤比水印本身更糟**。
所以改为提供**确定可用的手工通道**：用户在小猿搜题之类的站上搜到原题、重新截图，回来替换。

### 10.2 入口与链路

入口在「本卷配图总览」弹窗底部的新按钮 **「替换选中图」**（旁边是既有的 删除选中 / 批量转 TikZ），
三个输入方式共用同一条链路：

| 输入 | 说明 |
|---|---|
| 点击按钮选文件 | 隐藏的 `<input type="file" accept="image/png,image/jpeg,image/webp">` |
| 拖图片文件进面板 | 面板级 `drop` 监听 |
| **面板内 Ctrl+V 粘贴截图** | 面板级 `paste` 监听 —— 截图场景最快，用户描述的就是"截图出来再上传" |

链路：上传走**已有的** `POST /api/upload/batch`（内容寻址落盘到静态根目录）→ 换引用 → 重渲染卡片与图墙。

### 10.3 替换必须同步改四处（口径与软删除完全一致）

`replaceParsedCardImage(index, oldPath, newPath)`：

1. `q.image_paths` 换成本地图；
2. `q.content` / `q.answer_markdown` 里的引用换成新图 —— 两类形态都认：
   `![](/static/uploads/tmp/x.png)` 与入库结构层的 `\includegraphics{x.png}`（只写 basename）；
3. **两个编辑框的 value** —— ⚠️ 保存时读的是编辑框，不改就会被旧图覆盖回来（软删除踩过同一个坑）；
4. `content/answer_tikz_assets` 的 `reference_image_path` 改指新图（已生成的 `tikz_code` 仍然有效，**不要把资产删掉**）。

另外 `q.referenced_images` 一并替换；**原文件不删**（软替换），随时可以再换回来。

按 basename 替换时加了 `(?![\w.-])` 前瞻，否则 `pic_1_0.png` 会把 `pic_1_0.png.bak` 的前缀也吃掉。

### 10.4 顺带核实的两件事

* **第四方案（批量录入）前端入口是有的**：`index.html` 的 `tabBtn-batch`（标注「第四方案·批量」）
  + `tabContent-batch` 面板 + `import_batch.js`，`switchWorkflowTab` 的 tabs 数组也含 `'batch'`。
  看不到按钮时先**硬刷新（Ctrl+F5）**，并确认开的是 **27182**（8000 是上游，没有这个 tab）。
* **「前半原题 + 后半不重印题干」现在会被正确拒绝跳页**（§9.2 的第 7 道闸），不会丢题干。
  真要把它变成一道完整题，还需要「配对合并」（§4.4 方案 C），那是另一个功能。

## 1. 勘查事实

### 1.1 PDF 结构（17 页，**有文本层**，走 `native_preferred` 原生直提）

|---|---|
| p1–p4 | **原题**（纯题干，无解析、无答案） |

## 2. 已确认的 bug：页码基不一致（**P0 阻塞项**）

### 2.1 证据（脚本 `.system_generated/scratch/probe_page_index_basis.py`）

用真实 PDF 选**绝对页 `[5,6,7,8]`**（即第 6–9 页）跑裁剪：

```
产出裁剪图: 4
    pdf_crop_TID_5_0.png     ← 绝对 0-based = 5
    pdf_crop_TID_6_0.png
    pdf_crop_TID_7_0.png
    pdf_crop_TID_7_1.png

find_source_page_by_overlap 的基：
  命中第 1 个元素(绝对第 6 页) → 0
  命中第 4 个元素(绝对第 9 页) → 3
```

**同名流水线里同时存在三种页码基：**

| 口径 | 基 | 代码位置 |
|---|---|---|
| 裁剪图文件名 `pdf_crop_{task}_{p}_{i}.png` 里的 `p` | **绝对 0-based** | `pdf_inspector_helper._extract_fitz_pages:166`（循环变量就是 `page_index`） |
| `page_crops` 的 key（从文件名 `_crop_order` 取 `order[0]`） | **绝对 0-based** | `parsing_pipeline.py:510-522` |
| `q["_source_page"]` | **局部下标**（`enumerate(ocr_results)`） | `routes_ai.find_source_page_by_overlap:1353` → `parsing_pipeline.py:533` |
| 页文本里的页标 `<!-- MATHBANK_PDF_PAGE:N -->` | **绝对 1-based** | `routes_paper.py:1155`；`pdf_inspector_helper._page_marker:116` |

### 2.2 影响

- **只要用了 `页码范围`**，`_source_page`（局部）与 `page_crops`（绝对）就错位一个 `target_page_indices[0]` 的偏移 → 兜底配图**整体错挂或落空**。
- 前端卡片「源自第 N 页」显示的也是 `_source_page` → **用了页码范围就显示错页号**。
- 不填页码范围时（`target_page_indices = range(n)`）局部恰好等于绝对，所以这个 bug 一直没暴露。
- ⚠️ **本卷 17 页 < 80 页上限，用户大概率没填页码范围**，所以这**不是**本次"图挤最后一题"的成因；但它是**方案 A / B 的硬前提**（不管手动填还是自动切，都要先修）。

### 2.3 修法（二选一，推荐前者）

1. **让 `find_source_page_by_overlap` 返回绝对页**：页文本里已经带了 `MATHBANK_PDF_PAGE:{绝对+1}` 标记，直接解析它即可（零额外成本、无非连续页歧义）；解析不到时退回"局部下标 → `target_page_indices[局部]`"的映射（需要把映射传进去）。
2. 把 `page_crops` 的 key 换成局部下标。**不推荐**：文件名已固化绝对页，且任务清理逻辑按文件名走，改动面更大。

## 3. 方案对比

| 方案 | 做法 | 收益 | 代价 / 风险 |
|---|---|---|---|

## 4. 方案落地设计

### 4.1 P0：统一页码基

- 改 `routes_ai.find_source_page_by_overlap`：优先从页文本解析 `MATHBANK_PDF_PAGE:(\d+)` 得到**绝对 1-based** → 减 1 得绝对 0-based；解析不到再退回局部下标并加偏移。
- 补单测：喂含/不含页标的假 `ocr_results` + 非 0 起点的页范围，断言返回绝对页。
- 顺带核对前端「源自第 N 页」的显示口径（应显示绝对页，即用户翻 PDF 时的页号）。

### 4.2 D-①：把"每页重复的内嵌图"按水印丢掉

- **判据（两条都要满足，缺一不丢）**：
  1. **同一 xref 或同一像素尺寸的内嵌图在 ≥3 页上出现**（学科网 logo 4 页、校徽 12 页；正常插图极少这样复用）；
  2. 且 **位置贴页边**（页顶/底 4% 带内）**或 面积占比小**（复用 `illustration_crop._page_furniture_reason` 的阈值）。
- **落点**：`pdf_inspector_helper._extract_fitz_pages`（137–175 行，已有 `w < 20 or h < 20` 粗过滤的位置）。
- ⚠️ **单看"重复出现"会误伤**：同一张图被多道题合法引用（"参考下图"）是存在的 → 必须叠加"贴边/小面积"判据；且阈值要能在日志里打印出来，便于事后核对。

### 4.3 B：答案解析起点检测 + 默认只取后半

- **判据（只在"高置信"时才自动）**：
  1. 文本层出现**独占行的标题**：「参考答案」「答案与解析」「参考答案与解析」「详解」「答案详解」；
  2. 或第一处 `【答案】`/`【详解】`，且**其后每一页都有**（说明进入了逐题详解段），且**之前一页都没有**；
  3. 若该页只是"题号/答案对照表"（题号 + `A B C D` 表），起点应取**下一页**（本卷 p5 就是这种，起点应为 p6）。
- **落点**：`routes_paper.upload_pdf_task`（1389 起）——`page_range` 未填时先做检测，命中则把 `target_page_indices` 收敛到后半段，并**写进任务快照**供前端显示。
- **UI**：识别前显示「检测到第 1–4 页是纯题干原卷、第 5–17 页含答案与详解，**默认只识别第 6–17 页**」，并允许改回全篇。
- **风险与回退**：形态太多（有的卷子答案与解析分两段、有的只在卷尾给一张答案表）→ **检测不确定时保持全篇**，只打一条「疑似两段式，可考虑填页码范围」的提示，让用户自己决定。

### 4.4 C（备选）：题级去重合并

- 用 `题号 + 题干 3-shingle 重合度`（复用 `find_source_page_by_overlap` 的 shingle 手法）把"原题版/详解版"配对；保留 **`answer_markdown` 非空**的那份，`image_paths` 取并集且**原题版优先**。
- 需要一个明确的阈值 + 「不确定就不合并」，并把合并结果显示在计划/风险面板里供人工核对。

### 8.3 已修：#7 这类「大字水印」漏网

**为什么现有过滤放过它**：`classify_mineru_decoration_image` 的水印判据要求 `edge<=0.015` **且** `white>=0.80` **且** `area>=120000`（`mineru_client.py:440-443`）。而真实水印铺满后白色占比只有 **0.609**、面积只有 **55 680** → 两条都不满足。

**改法**（`mathbank/mineru_client.py`）：新增判据 2b —— **图上没有任何黑色墨迹 + 边缘极稀**：
```python
_GRAY_WATERMARK_MAX_EDGE_RATIO = 0.02
_GRAY_WATERMARK_MAX_BLACK_RATIO = 0.002
...
if edge <= _GRAY_WATERMARK_MAX_EDGE_RATIO and black <= _GRAY_WATERMARK_MAX_BLACK_RATIO:
    return "水印"
```
**依据**：数学图形必有黑色描边（坐标轴/曲线/字母）。实测真图形 `black` 最低 **0.007**（阈值的 3.5 倍）、`edge` 最低 **0.092**（阈值的 4.6 倍）→ 余量充足。
