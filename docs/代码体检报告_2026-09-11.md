## 三、优点

1. **后端分层落地扎实**：`mathbank/` 28 个模块全部被实际引用，无死模块；`paths.py` 统一锚定持久化路径，`ai_*` 三件套收敛了供应商判断规则，架构意图与实现一致。
2. **安全底线完整**：`MathBankSafe` 信任边界（DOMPurify 白名单 + 本地上传目录图片白名单 + 跨域 URL 拦截）在 `api.js` 中集中实现，后续 4 个前端模块全部走同一入口。
3. **语法零错误**：8 个 JS 文件全部通过 `node --check`；全部 Python 文件通过 `compileall`；未发现正则后行断言等兼容性禁令违规。
4. **测试投入度高**：37 个测试文件覆盖安全边界、数据库迁移、备份完整性、发布加固、并发事务等高风险面，并配有 GitHub Actions CI（pytest + JS 解析，Python 3.10 / 3.14 双版本）。
5. **规范意识强**：全仓库仅 1 处 `XXX`（且为文档字符串），无 TODO/FIXME 遗留；`.env` 已纳入 `.gitignore`。
6. **可解释的容错设计**：查重失败时明示"暂不可用"并放行保存，迁移采用备份优先 + 完整性校验，异常路径处理完整。

## 四、完整性缺陷（已确认为真实问题）

### 1. 测试基线：593 通过 / 1 跳过 / 7 真实失败

> 注意：直接运行会出现 24 个失败，其中 **17 个是环境问题**——当前 shell 未挂载 `node`，`shutil.which("node")` 返回 `None`，导致前端 `real_js` 护栏测试直接断言失败。挂载 Node 22 后真实失败收敛为 7 项。

| 失败项 | 性质 | 说明 |
| --- | --- | --- |
| `test_static_dialogs_expose_modal_semantics_...` | **真实缺陷** | `latexImportModal`、`lessonEditorModal` 缺失 `role="dialog"`、`aria-modal`、`aria-labelledby`，无障碍语义回归 |
| `test_generated_tailwind_classes_use_configured_scales` | **真实缺陷** | 代码使用 `brand-400`（4 处），但 Tailwind 仅配置 50/100/200/500/600/700/900，这些类不生效，暗色模式样式静默失效 |
| `test_duplicate_checks_are_click_triggered_...` | **文档-代码脱节** | 断言 `buildDuplicateAutoTag(...)` 存在于批量保存路径，但该函数全仓库不存在；仅 `editor.js:708` 有一处内联实现 |
| `test_category_refresh_only_reloads_editor_...` | 测试切片失效 | 报错 `normalizeCategoryTree is not defined`。经核实 `api.js:512` 定义与 `1682` 调用同属一个作用域，浏览器中正常，属测试脚手架切片边界失效 |
| `test_clear_and_session_reset_entries_...` | 测试切片失效 | `ValueError: substring not found`，测试检索的锚点文本已被重命名 |
| `test_api_stats` | 测试未同步 | API 返回 `l1_count`~`l4_count`，测试仍断言 `basic_count`（难度模型已重构） |
| `test_v10_to_v11_migration_rebases_topic_ids` | 测试未同步 | 期望 `to_version == 11`，实际为 12 |

**含义**：护栏测试已与真实代码脱节。这类测试的价值在于"改动即报警"，一旦失效，后续改动将失去保护。CI 配置存在但当前处于红灯状态。
